# Submission and visuals

## Tables and figures
Check sequential body references, captions, notes, panels, units, legends, decimals, significance marks, fonts, resolution, grayscale legibility, clipping, overlap, whitespace, and consistency with results. Captions should identify the exhibit; notes carry technical conventions; the body carries interpretation.

Benchmark the length of captions and table notes against published articles of the target journal before submission: count the words of every caption and note in three or four archived articles and in the manuscript, and report both to the author. A note repeats nothing the text already states (data sources, base-case parameters, definitions given in the methods, results derived in the text); it keeps only what a reader needs to read the table and what appears nowhere else. In the paper this rule came from, notes under all seven tables ran to 26–131 words, while four published articles of the target journal had one 25-word note in 27 tables; the author noticed before the assistant did.

## Declarations
Reconcile authorship contributions, funding, competing interests, ethics, consent, acknowledgements, data/code availability, AI-use disclosure, and author identity with the submission system. Portal statements may replace manuscript text, so store the final entered wording.

## Files
Check the journal's required manuscript, title page, cover letter, supplementary information, and separate figure files. Remove comments, tracked changes, hidden text, placeholders, working notes, personal metadata where anonymity requires it, and stale versions. Render Word/PDF files and inspect every page when tooling is available. "Every page" includes the reference list, each table and the caption list, not only the first page: a reference list joined with single line breaks renders as one run-on paragraph, and converter-default column widths break words inside table cells; neither shows in the markdown source or in a text diff. Look inside the tables at reading size, not only at a page thumbnail: a column narrower than its longest word breaks the word ("energ|y", "(KR|W/k|Wh)"), and a width rule that shrinks all columns in proportion when the table is too wide brings the breaks back for the widest table only.

## One defect found by the author is a class to audit
When the author points at one defect in a package (a Korean title in a reference, a paragraph with different line spacing), the fix is not that item. Name the class it belongs to ("text that is not in the journal's language", "formatting that differs from the rest of the file"), search every file of the package for the class by script and by reading the render, fix all instances at the source, and report what was searched, what else was found and what was clean. Then make the build fail on it next time (an assertion in the build script, for example: no non-Latin script characters in any file that goes to the journal; no author–year citation left in a numbered manuscript or its supplementary files), so the check does not depend on anyone remembering it. Minimum script audit before a package is called ready, each run over every file of the package including document properties and figure text: characters outside the journal's language; working marks (verify flags, "draft", file names and paths, placeholders, former affiliations or funders); citation scheme consistent across main text and supplementary files; spelling variety (British or American) consistent; the reference list read entry by entry. The author's words after the third such finding: "do I have to tell you every single one of these for it to be fixed?"

## Reference list
Build the journal's own reference style in the journal-specific package, from structured fields (authors, title, journal, volume, issue, year, pages, DOI), not by editing formatted strings. Read the style from the journal's official guide and from the reference list of a published article, and record the date. Where the guide accepts any consistent style at submission, say so to the author, and still make the list consistent: one capitalisation convention for titles (registry metadata mixes title case and sentence case), one author-name order, one entry per paragraph. Keep the generic list in the shared package so the next journal on the cascade starts from it.

Sources in another language. Every file that goes to the journal is in the journal's language only. A source published in another language (a regulation, a government notice, a news article, a national-journal paper) is listed with an English title followed by the original language in square brackets, for example "Notice on the direct power trading of renewable electricity, Notice No. 2025-61 [in Korean]"; the original-script title is kept in the literature record, not in the reference list. URLs are ASCII: where the permanent link contains non-Latin characters, give a numeric or ASCII link to the same document, or the site address with the document identified by its official name and number, rather than lines of percent-codes. Check the convention in two or three published articles by authors from the same country before choosing. In the paper this rule came from, three entries carried a Korean title in front of the English one and one carried a Korean URL; the author found them in the package that had been declared ready.

Supplementary files cite with the same scheme as the main text. When the main text is converted from author–year to numbers, the supplementary material is converted with the same number map (and says that reference numbers are those of the main text), or carries its own reference list.
